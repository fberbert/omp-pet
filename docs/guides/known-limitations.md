# Known Limitations

[Back to README](../../README.md)

| Limitation | Details |
|---|---|
| **OMP: state-only integration** | The pet observes OMP session lifecycle and tool events through a global extension. It does not intercept permissions or add confirmation prompts; OMP keeps its own execution behavior. Completion is recorded at the main-session `session_stop` and committed only by the following `agent_end` when `willContinue !== true`, so another extension's hidden continuation is not announced as finished. |
| **OMP: only one agent directory is managed** | OMP loads extensions from the **active** agent directory: `~/.omp/agent` by default, `~/.omp/profiles/<name>/agent` when `OMP_PROFILE` / `PI_PROFILE` is set. `PI_CONFIG_DIR` moves the config root and `PI_CODING_AGENT_DIR` relocates the profile-less default. The pet mirrors OMP's process-environment profile rules and installs into the single directory it resolves from its own environment. OMP can also read directory overrides from home, config, agent and project `.env` files; project `.env` varies by working directory, so one static install cannot follow every override. Run `npm run install:omp-extension` in the target OMP environment when needed. Doctor lists other on-disk profiles it does not manage. |
| **OMP: an unmanaged `omp-pet` extension directory is left alone** | If `<agent dir>/extensions/omp-pet/` exists without the pet's `.omp-pet-managed.json` marker, install and uninstall both skip it. Remove or rename the directory to let the pet manage it. |
| **OMP: no subagent animation** | The extension reports only main-session events. Subagent work keeps the session in its working state; the juggling animations are never triggered. |
| **OMP: no startup recovery** | If the pet starts while an OMP session is already running, it stays idle until that session sends its next event. |
| **OMP: extension changes need a new OMP session** | OMP loads extensions when a session starts. After the pet installs or updates its extension, sessions that were already running keep the previous copy (or none) until they are restarted. |
| **Terminal jump needs wmctrl or xdotool** | Raising the terminal window uses `wmctrl` (lookup by PID) with an `xdotool` fallback. Without either, Dashboard and HUD clicks do nothing. Terminals that host many tabs in one window are raised as a window; the pet cannot pick a tab. Inside tmux, the session's pane is selected after the raise. Other multiplexers (screen, zellij, herdr) are not reported by the extension, so only their window is raised. |
| **Local port** | The server listens only on `127.0.0.1`. It tries 23533 to 23537 first (starting with the port it used last), then a saved dynamic port, then an OS-assigned port. The current port is written to `~/.omp-pet/runtime.json`, which the extension reads to find the server. If that file cannot be written, a dynamic listener is closed; check the permissions of `~/.omp-pet/`. The range is separate from upstream Clawd on Desk (23333 to 23337), so both can run side by side. |
| **Linux/Wayland: limited dragging and cursor tracking** | Native Wayland forbids client-side window positioning and global cursor queries. Under a Wayland session with an X server available, the pet relaunches itself once under XWayland (`--ozone-platform=x11`), which restores positioning and dragging; cursor tracking is then limited to the pet's own surfaces. Full-screen cursor tracking needs a native X11 (Xorg) session. `OMP_PET_OZONE_PLATFORM` controls the automatic relaunch: `x11` forces it, `wayland` or `auto` keep native Wayland. An explicit `--ozone-platform=...` on the command line is always honored. Native Wayland is not a supported target. |
| **AppImage needs temporary runtime space** | Each FUSE launch copies the unpacked app to a private directory under `TMPDIR` (or `/tmp`) so an early unmount cannot remove code needed during shutdown. This needs enough free space on a filesystem that permits execution; on tmpfs it uses memory, and an XWayland relaunch can briefly need two copies. If the temporary filesystem is too small or mounted `noexec`, point `TMPDIR` at another writable, executable, non-FUSE location, or run an extracted AppDir. Normal shutdown removes the copy; a force-killed supervisor can leave it for the system's temp cleanup. If a shell starts the AppImage in the background with job control off and an ignored SIGINT, send SIGTERM instead of SIGINT to stop it. |
| **No in-app updates** | The auto-updater was removed. Update a source checkout with `git pull` and `npm install`; replace the AppImage or reinstall the `.deb` for packaged builds. |
| **Electron main process has limited automated coverage** | Unit tests cover the state machine, server routes, extension installer, settings and many runtime modules, but transparent windows, tray behavior, real dragging and focus still need manual checks. |
